- **PR #647 MERGED — fixed Secondary Injection labels on the ACB/NSX Test Report, plus a bigger sibling bug in the same lookup function.** Both `acb_test_readings`/`nsx_test_readings` store every electrical reading wrapped in `Electrical: ` by the save action (e.g. `Electrical: SI: Long Time - Trip Time (s)`) and every visual checklist row under `Visual Check: ` — but `findReading()`'s prefix-stripping regex only handled a bare `Visual:`, so it never matched `Visual Check: ...` at all. That meant #644's checklist relabel showed the right item names next to permanently blank results. Fixed the regex, and rewired the Protection/Trip Test Results tables (`buildProtectionResultsTable`/`buildTripTestTable`) to look up the real `SI: <Function> - <Field>` readings instead of a `Protection <name>`/`Trip <name>` label nothing ever wrote. Verified the checklist fix 12/12 against live NSX data on ehow (was 0/12); no live check has reached the Electrical Testing/SI step yet, so the SI-specific fix is verified via a synthetic end-to-end docx generation using the exact real stored label format. `tsc --noEmit` clean.

Live QA against the one real dataset on ehow found the dormant report template's checklist wording and CB-attribute lookups didn't match the real technician workflow (`AcbWorkflow.tsx`/`NsxWorkflow.tsx`) at all — relabelled ~35 checklist items and rewired ~20 breaker-attribute fields per generator to their real DB columns before shipping (#644). Report Settings' sign-off / cover page / executive-summary toggles, previously only respected by the Customer Report, now also apply to the Field Run-Sheet and PM Check Report (#645) and, after extracting the cover into `buildComplianceCover()`, the Compliance Report (#646). All default-safe (`?? true`) for tenants who've never touched Report Settings. Deferred: Secondary Injection test-result readings still don't match the report's lookup keys (same bug class, left out of scope); ACB path unverified against a real completed ACB check (none exist live yet).

Per-asset job plan lookup in `lib/reports/maintenance-checklist-input.ts` was already fetching the plan but only selected `id, name` — added `code` (the "Job Code" field, e.g. "SJPNL1") to that select and a new `ChecklistAsset.jobPlanCode`, rendered into the existing `ID | Location | WO` info line in `buildAssetSection` (`lib/reports/maintenance-checklist.ts`).
