# Session 2026-08-05-v — Root-caused the pending.md bloat as a 4-day-old broken cron, fixed it, then closed the actual gap as F11

## Built
- Royce asked why the session gate was suddenly finding so many items. Traced it: `digest.md`'s Needs You feed genuinely did get richer recently (security-register + Sentry surfacing, both real 2026-08 additions) — but the specific complaint (`eq/pending.md` at 500KB) was not organic growth. `gh run list --workflow=pending-rotate.yml` showed 4 consecutive failed nightly runs since 2026-08-01; `gh run view --log-failed` pinned the exact cause: `git add ... ops/verify-queue.md` fatal ("did not match any files") under `set -e`, because that file is only created once OPS has a verify item to move, and never has.
- Royce then asked "we only went through this all recently? are you sure" — correct instinct. Commit `c5fbe4f` (09:31, 2026-08-01, `/decide` with Royce) had just fixed this exact bloat problem by adding the verify-queue split. Commit `b8a7bc4`, four minutes later in the same session, wired the new files into `pending-rotate.yml`'s `git add` list and introduced the bug that silently undid the fix the same day.
- Fixed in an isolated clone (not the shared checkout — ~100 commits/day of concurrent traffic right now): `pending-rotate.yml`'s `git add` now only adds files that exist. Ran the catch-up rotation for real: `eq/pending.md` 500KB → 443KB (127 done + 17 verify items moved), plus SKS/OPS. Rotation engine's own test suite (43/43) run clean first; binary NUL scan clean after. Pushed to `main` (`20c73f05`) with Royce's explicit go-ahead, rebased once past a concurrent commit mid-push, verified clean after.
- Royce asked for a guard against this class recurring. Built `scheduled_workflow_health()` in `refresh_digest.py`: discovers every `.github/workflows/*.yml` carrying a `schedule:` trigger at read time (never a hardcoded list — a hand-maintained list of "files that should exist" is the same drift class that caused the bug), checks each against its own `event=schedule` GitHub Actions run history, and feeds consecutive-failure findings into `digest.md`'s Needs You — the same pipeline `hooks/session_start.py` already reads unconditionally every session. Pure counting logic (`_scan_run_conclusions`) split out and unit tested (8/8, new `test_scheduled_workflow_health.py`), wired as a pre-flight CI step in `digest-refresh.yml`, matching the "test before trusting a script that writes the substrate" posture `pending-rotate.yml` already holds. Filed as `system/failures.md` F11.
