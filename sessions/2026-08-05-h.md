## Notes

- **Recurring operational snag worth knowing about**: after a `gh pr merge --squash`, the source branch's local commit history no longer fast-forwards from `main` (main gets a *new* squashed commit, not the original branch history). Continuing work "in the same sitting" on that same branch produces a stale-looking diff against `origin/main` even though the content is identical. Hit this twice this session — fixed each time by cutting a fresh branch off updated `origin/main` and cherry-picking the new commit onto it, rather than trying to rebase the old branch. No functional harm, just an extra step to remember when a session ships several sequential features and merges as it goes.
- **A close-time collision on the shared `eq-context` checkout, caught live, not just described.** This session's own close ran straight into the exact shared-checkout race documented elsewhere in this file (F9): the local checkout already had two other sessions' unpushed "session close" commits stacked ahead of this one, a `git rebase onto origin/main` hit an add/add conflict on a session-log filename claimed independently by two different sessions, and — worse — mid-resolution, `git status` surfaced untracked files (`sessions/2026-08-05-h.md`'s predecessor slot, then `-i.md`) that turned out to be **other sessions' live, uncommitted, in-progress writes to the same working tree**, not settled history.
