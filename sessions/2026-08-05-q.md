# Session 2026-08-05 (q) — Adversarial-suite false-failures root-caused to two harness bugs, not F9

## Built
- Root-caused the 3 cases failing in both `hooks/adversarial_test.py` and `.sh` on origin/main. Not an F9 interaction (the suspected cause) — two independent, pre-existing bugs in the harness itself:
  1. `targets_mount()` requires a literal `/projects/` path segment, so the suite's own F2/F7 fixtures fail from any clean-room clone placed elsewhere, on any commit (proved via commit `37989be`, pre-dating today's F9 work, failing identically from a bad location).
  2. `adversarial_test.sh` only: Git-Bash/MSYS auto-translates POSIX-looking env vars to Windows-style paths when launching a native `python3.exe`, but not the same-looking text inside a JSON payload piped over stdin — `EQ_MOUNT_ROOT` and a `$R`-based file path silently stopped matching.
- Added an `EQ_MOUNT_ROOT` override to `targets_mount()`/`resolve()` in `hooks/pre_tool_use.py`, mirroring the existing `EQ_CONTEXT`/F9 pattern — inert in every real session. Wired into both test files; `.sh` also routes `$R` through `cygpath -w` for JSON-embedded paths.
