# Session 2026-08-05 (k) — Shell-embedded Field nav bar: root-caused and fixed (two PRs)

## Built
- eq-field v3.5.456 ([PR #651](https://github.com/eq-solutions/eq-field/pull/651)): scoped the `.shell-mode` touch-nav-restore media query from `pointer:coarse` alone to `pointer:coarse and hover:none`, so a touchscreen desktop/laptop driven by a mouse no longer falsely matches. Real fix, but not the cause of what Royce was actually seeing — deployed, confirmed live, his screen didn't change.
- eq-field v3.5.457 ([PR #652](https://github.com/eq-solutions/eq-field/pull/652)): found and closed the real bug. `mobile.css` hides `.sidebar` unconditionally at any width ≤768px; the `.shell-mode` mobile-nav restore was gated to touch devices only. A shell-mode iframe that goes narrow on an ordinary mouse-driven desktop matched neither rule — sidebar hidden, mobile-nav hidden by `base.css`'s unconditional `!important` — no navigation at all. Fixed by OR'ing `(max-width: 768px)` into the same media query.

## Decided
- No new business/scope decisions this session — this was a bug investigation and fix, not a feature.
