# Session 2026-08-17 (continued) — audited the other two sign-in doors for the same silent-lockout bug, fixed both, shipped

Royce asked to check whether the PIN-reset silent-inactive-account bug (fixed earlier this session, PR #1417) also existed on eq-shell's other self-service sign-in doors.

## Built

- Audited all three remaining self-service auth doors in eq-shell:
  - **`shell-login-magic-link.ts`** — a real gap, worse than PIN-reset's: this door runs *after* the caller has already proven their identity via a valid Supabase token, so there was never an enumeration reason to hide "account inactive" from it — and yet it had **zero** audit trail for that case, not even a log line (PIN-reset at least had the anti-enumeration justification for its silence). Fixed: query no longer filters `active=true` (so "no row" and "row exists, inactive" can be told apart), added `auditLoginBlocked` (new `account-inactive` reason) + `captureInactiveAccountRequest` on the inactive branch. Client response unchanged.
  - **`shell-login-phone-otp.ts`** — smaller gap: already had an audit trail (`auditLoginBlocked`), but its `no-memberships` reason collapsed "never provisioned" and "provisioned then deactivated" into one label — the exact ambiguity that made Richard Brown's lockout earlier this session look like he'd never signed up. Added a targeted inactive-match check with its own `account-inactive` reason before falling through to the generic one. Client response unchanged.
  - **`shell-login-phone-pin.ts`** — audited, deliberately left untouched. Its identical no-account/no-pin/wrong-pin response is a documented anti-enumeration property (the file's own header comment explains at length why: AU mobile numbers are a small enough space that any distinguishing signal becomes an oracle, and explicitly warns against reintroducing one). Fixing this would have undone real security, not added real observability.
- Extended `auditLoginBlocked`'s `reason` type (in the shared `_shared/login-audit.ts` vocabulary module all four doors already used) with `account-inactive`, rather than inventing new ad-hoc logging.
- Generalized `captureInactiveAccountRequest`'s `toDomain` param to `identityHint`, since phone-keyed doors have no email domain to report — updated all three call sites, including the one already merged in #1417.
- Fixed one pre-existing, unrelated `prefer-const` lint error while in `shell-login-phone-otp.ts` (not introduced this session, but in a file being edited).
- Verified before shipping: `tsc -b tsconfig.netlify.json` clean, `eslint` clean (0 errors), full function test suite 268/268 pass.
- [PR #1418](https://github.com/eq-solutions/eq-shell/pull/1418) — opened, merged (squash), confirmed live (production deploy's `commit_ref` matched the merge commit within seconds).
