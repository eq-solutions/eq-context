- **Incident 1 — migration dispatch failed on both tenant planes, not caught until the dependent app code was already live.** `CREATE OR REPLACE VIEW` matches columns by *position* — the new column had been inserted mid-list instead of appended, which Postgres reads as a rename, not an add (`42P16`); the migration also wrongly targeted the `eq` tenant, where the equivalent table is a plain base table, not a view. Because the already-shipped roster-write code unconditionally sent the new column in every canonical save regardless of the (OFF) toggle, every Edit Roster autosave on live SKS was at risk, not just ones touching the picker. Caught within minutes by checking the dispatch's own run log directly, not assuming success. Fixed same-day: eq-field [PR #827](https://github.com/eq-solutions/eq-field/pull/827) (hotfix — omit the key rather than send `null`) + eq-shell PR #1661 (column moved to the end of the view's column list, re-dispatched, confirmed live).
- **Incident 2 — a stale browser tab silently undid a live data fix, three separate times.** Unrelated root cause to Incident 1: eq-field's canonical roster save (`_sbRosterCanon`'s `_replaceWeek`) always blind-deletes-and-reinserts a person's *whole week* from whatever's in the browser's memory, with zero check against what the server currently holds — a tab open since before any server-side change silently clobbers it the instant it next saves anything in that week. Caught each time via a changed `schedule_id` + a fresh `updated_at` (proof of a real re-save, not a stale render) — the third occurrence's timestamp matched a live screenshot's own "Updated" banner to the minute. Ran `/decide` against three staged fix options (realtime sync / compare-and-swap / both + a tab-focus refresh) before building; shipped the CAS guard plus the one slice of the realtime fix it turned out to depend on (a pre-existing gap where project-code changes never live-synced at all), as eq-field [PR #829](https://github.com/eq-solutions/eq-field/pull/829) (v3.5.601). New `tests/supabase-canon-write.test.js` — first-ever coverage for this save path, the same one that needed Incident 1's emergency hotfix. Named tradeoffs in the PR itself: week-granularity (not per-day) CAS, and not retroactive for a tab already stale when it shipped.
- **Feature addition, prompted live by Incident 2**: three independent real-world attempts to type the *project* code ("MOD10") into the roster's *site* cell, reframed by Royce as a real feature request rather than user error — "Users will want to type MOD10 - how do we do that and make it reference SLDC site info?"
