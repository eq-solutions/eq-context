# Session 2026-08-05-r — Fixed the effective_cwd() cd-regex anchoring bug found earlier today

## Built
- Fixed `hooks/pre_tool_use.py`'s `effective_cwd()`: the `cd` fallback regex was anchored with a bare `^` (start of the whole command string, not a line start), so a `cd` preceded by an earlier line — e.g. a variable assignment — was invisible to it and fell through to the session's nominal cwd, false-blocking a rebase genuinely running inside an isolated clone. Fixed with `re.MULTILINE`. Confirmed `git -C` had no equivalent gap (never `^`-anchored) rather than assuming it.
- Added 4 regression cases to `hooks/adversarial_test.py`, mirroring the existing `nominal_cwd`/2104668 test block: the bug reproduced, the actual rebase-verb shape that false-blocked live, a `git -C` control, and an over-match control. 79/79 python, 36/36 bash, 0 regressions.
