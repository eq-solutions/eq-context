## Notes
- **Real bug pattern worth remembering**: `CREATE OR REPLACE FUNCTION` only replaces a function with an *identical* argument-type signature. Adding a new optional param (or a caller passing a different arg count) silently creates a **second, additional overload** rather than updating the one actually invoked. `job-creation.ts` uses `getTenantRpcClientById` — a service-role client with no `request.jwt.claims` — so it always calls the 2-arg `eq_get_job_creation(p_quote_id, p_tenant_id)` overload (added in migration 0121 specifically to work around the missing JWT context); new fields added to a bare 1-arg version in 0197/0198 never had a code path that could reach them. Any future RPC signature change should grep `pg_proc` for existing overloads of the same name before assuming `CREATE OR REPLACE` covers it.
- JSX/TSX structural-balance bugs during the PR #1004 layout refactor were only reliably diagnosed with the TypeScript compiler API (`ts.createSourceFile` + `sf.parseDiagnostics`, AST-walk printing `JsxElement`/`JsxFragment` line ranges) — a hand-rolled regex div-tracer gave false positives/negatives on multi-line tags and ternary-branch JSX fragments.
- Hit the recurring shared-checkout race twice this session (another concurrent session had `main` checked out on the same physical worktree root, once mid-task and once during `gh pr merge`'s local cleanup step) — worked around both times per the documented pattern (stash, branch from fresh `origin/main`, delete the remote branch via `gh api` when local cleanup can't run).
