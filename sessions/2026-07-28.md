# Session 2026-07-28 — Roster: archive Labour Hire from the grid with a rehire rating

## Built
- Roster editor (`sks-nsw-labour`): Labour Hire rows get a 📦 archive icon (other groups untouched) that opens a small modal with an optional 1–5 star "would rehire" rating before archiving. Archiving stays reversible, same mechanism as the existing People-page archive.
- People page: already-archived Labour Hire rows get a ☆/★ rate action so the rating can be set or corrected after the fact, not just at the moment of archiving. A star chip shows next to the name wherever a rating is set — including a restored (rehired) worker, so the signal doesn't disappear once they're active again.
- New nullable `rating smallint` column (CHECK 1–5) on `people`, applied live to the sks-labour Supabase project (`nspbmirochztcjijmcrx`) via `apply_migration`, verified before and after.
- Follow-up fix in the same session: the archive-from-roster modal always opened with a blank star picker. Re-archiving a restored worker without picking a star silently overwrote their earlier rating with `null`. Fixed to prefill from the worker's current rating (same as the People-page rate action) — leaving it untouched now preserves it.
- v3.10.104 (PR #71) and v3.10.105 (PR #72) both merged to `main`, both branches deleted. Netlify auto-deploys `main` → sks-nsw-labour.netlify.app.

- Rating is a standing signal, not an archive-time snapshot: restore doesn't clear it, and re-archiving now preserves it by default (Royce's explicit call, asked after noticing the gap wasn't discussed up front).

The merge itself completes via the GitHub API first; verified both times via `pull_request_read` (`merged: true`) before treating it as done, then deleted the now-merged remote branch manually (`git push origin --delete`) since `gh`'s post-merge cleanup didn't run.
