## Notes
- **Real git-mechanics incident, caught before it shipped:** rebasing the EQ Field branch onto `origin/main` hit the version-bump-line conflict pattern documented below; running `git commit --amend` while HEAD was still detached at the conflict-paused rebase amended `origin/main`'s own commit (PR #640, unrelated map-anchor fix, wrong author) instead of creating a new commit on top of it — silently squashing two unrelated releases together. Caught by noticing the resulting commit touched 8 files instead of the expected 6, not by trusting a green rebase. Fixed by resetting to the clean pre-rebase branch tip and redoing the integration as a `git merge` instead — fails safe to a normal push, no force/history-rewrite needed. A `--force-with-lease` attempt was also correctly blocked by the session's auto-mode classifier, which is what pushed toward the merge-instead-of-rebase fix in the first place.
- **New recurring collision pattern worth knowing about:** in both repos, when two concurrent branches each bump the SAME version-tracking lines (`APP_VERSION`, `sw.js` CACHE string, script `?v=` cache-bust tags) to the exact same next-integer version, a plain `git rebase`/`git merge` auto-resolves those lines as non-conflicts (identical text on both sides) — silently leaving two unrelated releases claiming the same version number. Not caught by git; only caught by manually diffing the touched-files list against what the change actually contains. This happened for real on EQ Field this session (PR #640 also claimed v3.5.446); resolved by manually renumbering to the next free version.
- EQ Field's `docs/reflection-log.md` has a hard commit-time gate (`reflection-gate` in `guard.js`) requiring a reflection entry staged in the same commit as any code change — not documented in the global session-gate rules, discovered live when the first `git commit --amend` attempt was blocked. SKS NSW Labour has no equivalent gate.
