# Session 2026-07-29 — eq-receipts: fixed a duplicate-detection blind spot, added invoice number as a stronger match

## Built
- Traced a live bug: two identical Anthropic charges ($12.02 USD) weren't flagged as duplicates because the duplicate check compared the AUD-converted total, and the currency conversion rate applied can drift a few cents between two scans of the same document.
- Fixed the check to compare the original as-charged amount instead, for foreign-currency receipts — no longer sensitive to which day's conversion rate got used.
- Added invoice/receipt number as the strongest match when a document prints one — more reliable than amount+date for recurring subscription charges.
- Re-ran the corrected check against every existing receipt — surfaced a second real duplicate that had been hiding the same way (two GitHub charges, $68.64 USD, both already approved, 2026-07-22).
- Shipped end-to-end: eq-receipts [PR #14](https://github.com/eq-solutions/eq-receipts/pull/14) merged, frontend live via Netlify auto-deploy, backend (extract-receipt, poll-batch, receive-email edge functions) redeployed to Supabase.

- Royce: fix both the FX-instability bug and add invoice_number as a stronger signal, rather than just the narrower fix.
- Royce: push, merge, and deploy the edge functions — all explicit go-aheads, done in sequence this session.

# Session 2026-07-29 (cont.) — EQ Field: team pills as the single crew picker, plus a lazy-load race and a column-sizing bug

## Built
- Royce asked for a team selector on Edit Roster, "same as SKS NSW". Investigation found the pill UI already existed (`teams.js`, ported from SKS once before, v3.5.27) but was missing from Editor, and — everywhere it did render — never actually filtered anything (`personInActiveTeam()` was never called from any page's render function). A separate "My crew / a team / Everyone" dropdown was the only thing actually scoping fetches (Roster + Timesheets), also absent from Editor and Contacts.
- Consolidated onto the pill row as the single picker everywhere (eq-field [PR #563](https://github.com/eq-solutions/eq-field/pull/563), v3.5.375): wired `personInActiveTeam()` into Editor/Roster/Contacts/Timesheets' render functions; `getCrewPersonIds()` (permissions.js) now reads `STATE.teamFilters` instead of the retired `EQ_CREW_VIEW`; added three-state persistence (never-chosen / explicit-All / team ids) so a supervisor who's never touched the pills still defaults to their own crew, matching the old dropdown's default; removed the dropdown UI; rewrote `tests/crew-scoping.test.js`'s manual-widen section for the new mechanism (35/35 pass).
- Real behavior change flagged up front: Contacts and Editor previously always showed everyone regardless of crew — this is the first time either page gets any default narrowing.
- Royce reported the pills still weren't showing on `core.eq.solutions/sks/field?tab=editor` after a hard refresh. Root-caused (not assumed): the deployed code was correct, but `renderTeamPills()` had a lazy-load race — only ever called before `teams.js`'s async lazy-load necessarily resolved, or (post-load) only for the `'teams'` page specifically. Same bug class this file has already fixed twice for `leave.js`. Invisible before because normal in-app navigation usually pre-loaded `teams.js` from an earlier tab; Core's cold `?tab=editor` deep link has nothing to paper over it. Fixed by calling `renderTeamPills()` from inside `renderCurrentPage()`, which only ever runs after the lazy-load resolves, for every page (eq-field [PR #565](https://github.com/eq-solutions/eq-field/pull/565), v3.5.377).
- Found and fixed a second bug in the same screenshots: Labour Hire rows' 4th action-column icon (📦 archive, from an earlier session's v3.5.371) overflowed `.editor-actions`' fixed 80px width, which was never widened when that icon was added — misaligning Labour Hire rows against the header and every other group. Widened to 108px, same PR.
- Answered two follow-up questions by reading the actual code rather than guessing: Copy Last Week / Copy Week → copy the whole roster's schedule data for the source week, not whatever's filtered by a team pill; TAFE Holidays is a date-range blocklist that stops the "Apply TAFE Day" button and the Sunday automated cron from auto-filling apprentices' TAFE days during those ranges — adding a range doesn't touch anyone's roster by itself.

## Decided
- Royce: pills become the one true crew-picker mechanism across all four pages, retiring the dropdown — asked directly given building both properly would've left two competing pickers on some pages.
- Royce: "merge" — both PR #563 and PR #565, each confirmed separately.
