- **Found a second, distinct hook bug while recovering from the above** (first one — the `guard.js` leading-slash bug — already spun off as `task_ec3c7cf0`, now running): `hooks/pre_tool_use.py`'s `effective_cwd()` uses `re.search(r'^\s*cd\s+"...")` — `^` anchors to the start of the *entire command string*, not the start of a line, so a `cd` on any line after a preceding `VAR=value` assignment line never matches, and the function silently falls back to the session's nominal starting cwd. This made the F9 shared-checkout rebase guard block a `git rebase` that was genuinely running inside an isolated clone (correctly `cd`-ed into via a preceding variable assignment) — a false positive with the exact same *shape* as the `guard.js` bug (a regex that only handles the single-line/no-preceding-content case) but in a different file, different mechanism (anchoring, not path-normalization), and not yet flagged anywhere. Workaround used here: put `cd "<literal path>"` as the literal first token of the command, no preceding variable line. Not spun off as its own background task this session (already spawned two; flagging here for whoever picks up `task_ec3c7cf0` or a future session to fix alongside it, since the fix is the same shape — use `re.MULTILINE` or search for `cd` anywhere via `re.search(r'(?:^|\n)\s*cd\s+...', ..., re.MULTILINE)` instead of anchoring to the whole string).
