# Session 2026-08-05 (e) — WebOTP auto-fill for Cards phone sign-in, and the manual-deploy gate it exposed

## Built
- Root-caused Royce's "Samsung phone won't autofill the PIN code" + "not logging into cards automatically" reports as one and the same thing: Cards renders via Flutter's CanvasKit renderer (the alternate HTML renderer no longer exists in this Flutter SDK), which paints to a `<canvas>` rather than real DOM inputs, and nothing in the app was listening for the incoming SMS at all.
- Built a `WebOtpListener` (`eq-cards/lib/features/auth/data/webotp_bridge.dart` + `_stub.dart` + `_web.dart`, same conditional-export pattern as the existing `shell_bridge.dart`) that auto-fills and auto-submits the OTP field the instant a correctly-tagged SMS arrives. Feature-detects via `'OTPCredential' in window` — Chrome/Android only, falls straight through to today's manual entry on every other browser (all of iOS included) or if the tagged SMS never turns up. Wired into `otp_screen.dart`'s phone-OTP path only.
- Real build snag: first implementation used `dart:js_util`, which turned out to have been removed from this Flutter SDK (`>=3.32.0`) entirely — `flutter analyze` caught it immediately (`Target of URI doesn't exist`). Rewrote using `package:web` + `dart:js_interop`, the modern bindings this codebase has already migrated other web-only files to (`photo_cache_web.dart`, `photo_compress_web.dart`). `package:web`'s generated bindings cover the WebOTP *request* side (`OTPCredentialRequestOptions`) but not the result type's `code` property, so that one property read goes through the `dart:js_interop_unsafe` escape hatch.
- A fresh worktree checkout had zero generated `.g.dart`/`.freezed.dart` files (riverpod/freezed codegen output is gitignored) — `dart run build_runner build --delete-conflicting-outputs` first, which also explained an unrelated wall of ~1700 pre-existing analyze errors that had nothing to do with this change.
- eq-cards [PR #213](https://github.com/eq-solutions/eq-cards/pull/213) — analyzer clean, 260/260 tests pass, squash-merged (`e2ca208`), worktree + branch cleaned up.
- Gave Royce the exact SMS-template text and steps for jvkn's Supabase Auth dashboard (Authentication → Templates → SMS Message) — not reachable through the data-plane Supabase MCP tools available in this session, so it had to be a manual dashboard edit. Royce applied it.
- **Royce reported "still didn't work" after merging + updating the template.** Traced it live: eq-cards' `deploy.yml` is deliberately `workflow_dispatch`-only (its own header comment explains why — merging to main used to auto-deploy, which conflicted with the "never deploy without explicit instruction" rule, so it was changed to manual-trigger-only). The last production deploy predated the PR #213 merge by ~8 hours. Confirmed via the live bundle: `main.dart.js` had no `OTPCredential` string before triggering a deploy, and did after. Got Royce's explicit go via AskUserQuestion, triggered the deploy; he's since re-triggered it a few more times himself for other merged work. **Confirmed live** as of session end — the current production bundle contains the WebOTP code.
- Found and closed a stale duplicate: `eq/pending.md` had a parked "Android OTP autofill (WebOTP)" item from 2026-07-12 describing this exact same gap (SMS template line already added back then, JS shim flagged as the missing piece, parked on Royce's "probably not end of the world"). Marked it closed with a pointer to PR #213 instead of leaving two open threads describing the same problem.
