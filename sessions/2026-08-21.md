- **A previously-unknown, load-bearing CI constraint surfaced mid-merge**: this repo's CI has a "Guard function filenames" step that fails the whole `typecheck · test · lint` job (and would fail every real Netlify deploy) if any top-level file in `netlify/functions/` has a name outside `[A-Za-z0-9_-]` — Netlify treats every top-level file there as a function-deploy candidate, and `.test.ts`'s embedded dot trips it. Every existing test in this directory (33 of them, checked) already lives under `netlify/functions/_shared/` for exactly this reason — moved the new one to match. - **Self-caught process mistake, not user-flagged**: after moving the test file, ran `git add -A <new-path> <old-path>` where the old path no longer existed post-rename — the nonexistent second pathspec silently failed the ENTIRE add, so only the bare `git mv` (no content fix) got committed and pushed. `git status --short` showed `RM` for the file, which does mean "still has unstaged changes" but reads easy to misparse as just confirming the rename. CI's typecheck job caught it (`Cannot find module`). Fixed by re-adding and explicitly checking `git diff --cached` for the real content before committing this time, rather than trusting `git status`'s summary line alone — worth carrying forward as the actual verification step after any git operation that touches multiple related paths.
