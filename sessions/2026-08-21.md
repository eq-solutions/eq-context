# Session 2026-08-21 (spans back to 2026-08-20) — eq-service Shell session keepalive fixed, merged, confirmed live

## Built
- Root-caused and fixed a live auth defect in `ShellTokenRefresh.tsx`: the keepalive that renews a Shell-embedded tech's `eq_service_jwt` cookie every 4 hours gave up permanently after any single failed refresh attempt (three separate exits, including a `try/finally` with no `catch` at all letting a thrown `fetch` escape unhandled). One ~15s window per 4h session was the entire refresh budget — a single dropout there silently killed the tech's session for good.
- Rewrote it to retry every failure path on a capped exponential backoff (15s→30s→60s→2m→4m), with `online`/`visibilitychange` listeners for instant recovery, and a `SessionExpiredBanner` that only appears once the cookie has actually expired and a retry has failed (never while still silently working).
- Deliberately kept retries going past the cookie's technical expiry, against the originally-suggested design — `/api/shell-auth` mints from the incoming Shell token, not the existing cookie, so post-expiry recovery genuinely works and stopping there would have thrown away the plant-room recovery case the fix exists for.
- Extracted the scheduler out of the React component into `lib/auth/shell-token-keepalive.ts` specifically so it could be unit-tested — wrote 15 tests, then proved they weren't vacuous by reintroducing the original defect verbatim and confirming 8 of 15 fail against it.
