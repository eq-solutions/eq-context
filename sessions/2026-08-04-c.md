# Session 2026-08-04 (c) — Status-enum pre-commit guard, and the hook that was never running

Continuation of `2026-08-04-b.md`, after PR #125 merged. Royce: "add the

## Built

- **`.githooks/pre-commit` check 17.5 (new)** — blocks any governed `.md` whose frontmatter `status:` is outside `live|draft|archived|deprecated`, or is missing the key entirely. The exemption list is held byte-identical to `.github/workflows/frontmatter-check.yml`; if the two drift, the hook either blocks what CI allows or waves through what CI rejects, and both teach you to distrust it.
- **The governed hook now delegates to `scripts/pre-commit-secrets.sh`**, fail-closed if that script is missing. See below for why this was mandatory rather than nice-to-have.
- **`scripts/install-hooks.ps1`** — now refuses to run without the secret-guard script, warns that any `.git/hooks/pre-commit` will be shadowed once `core.hooksPath` is set, and lists the two guards it actually installs.
- **`system/failures.md` F8 (new)** — prose in the frontmatter status field, `recurrences: 2`, rung 3 → 4. Also added `sessions/2026-08-04-b.md` and this file to F6's `confirmed_in`.

## The real finding: the hook had never run on this machine

While wiring the check I ran `git config core.hooksPath` and got
`C:\Projects\eq-context\.git\hooks` — **not** `.githooks`. So the repo's
governed 9KB pre-commit hook had never executed on this clone. This is the
2026-05-24 `core.hooksPath` lesson recurring, and it means every style rule in
that file has been decorative here for an unknown period.

**The trap, and why the obvious fix would have been a downgrade:** the hook
sitting in `.git/hooks/pre-commit` is not stale junk. It is a *secret-pattern
guard* — GitHub PATs, Supabase JWTs, AWS/Stripe/Anthropic keys — byte-identical
to the tracked `scripts/pre-commit-secrets.sh`. Git uses `core.hooksPath` **or**
`.git/hooks`, never both. Simply pointing `core.hooksPath` at `.githooks`, which
is what `install-hooks.ps1` did and what the lesson file recommends, would have
**silently disabled credential-leak protection** in exchange for frontmatter
checking. A strict downgrade against `rules/non-negotiables.md` #7.

Fixed by delegation instead: the governed hook invokes the secret guard first,
and refuses to commit at all if the script is absent. Both guards now run from
one version-controlled entry point.
