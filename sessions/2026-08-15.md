# Session 2026-08-15 — eq-shell: account-enumeration oracle closed on the phone+PIN sign-in door, then the timing-burn hash deduped

## Built
- **[#1355](https://github.com/eq-solutions/eq-shell/pull/1355) MERGED (`81b3a1a0`) + live** — closed two account-enumeration oracles on `netlify/functions/shell-login-phone-pin.ts`, both the class [#1350](https://github.com/eq-solutions/eq-shell/pull/1350) had just closed on the email door.
  - **Body oracle:** "no account / no PIN" returned `200 {valid:false, error:'no-pin-set'}` while a wrong PIN returned a bare `{valid:false}` — distinguishable, so it confirmed account existence for any AU mobile submitted. All three cases now return a byte-identical bare `{valid:false}`. The in-code comment defending this was true *within* the not-found branch but said nothing about the difference against the wrong-PIN branch, which was the actual leak.
  - **Timing oracle:** the not-found branch returned before `bcrypt.compare`, making "no account" ~270ms faster. Added the `NO_USER_DUMMY_HASH` burn. Measured after: 254ms vs 275ms (21ms residual = bcryptjs variance).
  - `src/pages/LoginPage.tsx` — one message for every rejection, pointing a PIN-less worker at the "Text me a code instead" button already on that form.
- **[#1359](https://github.com/eq-solutions/eq-shell/pull/1359) MERGED (`8bf83a79`) + live** — folded the duplicated `NO_USER_DUMMY_HASH` into `netlify/functions/_shared/pin-timing.ts` (constant + a `burnPinCompare(pin)` helper returning void, not the always-false result). Both doors import it. Added `_shared/pin-timing.test.ts` (4 tests) asserting the hash parses as bcrypt **at cost 12**, matches nothing, yields no boolean, and costs the same as comparing against a freshly-hashed real PIN.
