## Notes
- **Real git gotcha worth remembering for any future rebase-conflict resolution in a repo with a commit-time gate hook (like eq-field's reflection-log pre-commit check):** during a paused, conflicted `git rebase`, HEAD is detached at the rebase target (the "onto" commit), not at a new in-progress commit. Running `git commit --amend` at that point amends the ONTO commit itself — rewriting someone else's already-merged history, reparented onto ITS parent — instead of creating a new commit layered on top of it. `git rebase --continue` is the only safe way to finish a conflicted rebase once conflicts are resolved and staged; never substitute a manual `commit --amend` for it. The bug is easy to miss because the working-tree content is often still fully correct (it was here) — only the commit's parent pointer is wrong, which surfaces as GitHub reporting the PR "CONFLICTING" even though a local `git diff` against the target branch shows nothing unexpected.
- **Separately confirmed:** eq-field's `eq-guard` reflection-gate pre-commit hook blocks the entire Bash tool invocation if the string "git commit" appears anywhere in the command, even when a `git add` is chained before it with `&&` — the whole compound command gets blocked before any part of it runs. `git add` and `git commit` must be issued as separate tool calls here, or the add silently never happens.
