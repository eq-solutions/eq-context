# Session 2026-08-12 → 2026-08-13 — eq-shell: unreachable upload-size limits fixed suite-wide, direct-to-storage attachment upload built, 2 dead storage buckets removed, EQ-SHELL-1J root-caused + fixed

## Built

Traced to Netlify's hard 6 MB synchronous function payload ceiling — several functions claimed `MAX_BYTES` of 10–20 MB, but multipart/base64 inflation in transit meant only ~4.5 MB was ever actually reachable. Any file in that gap failed at the network layer before the function ever ran, and the generic client catch showed a misleading "check your connection" instead of a size error.
- Fixed across 8 functions (`staff-licence-backfill`/`-ocr`/`-replace-photo`, `upload-asset-cert`, `upload-document-version`, `ocr-parse`, `labour-hire-parse`, `create-worker-invite`) + every frontend caller — `MAX_BYTES` lowered to a reachable 4 MB, honest error messages, instant client-side pre-checks. `create-worker-invite.ts` needed a combined-total check too, not just per-file (it can carry several licence documents in one request body). eq-shell [#1307](https://github.com/eq-solutions/eq-shell/pull/1307), merged + deployed live.
- Royce clarified the real remaining pain was narrower and bigger at once: plain quote reference attachments (drawings/PDFs/emails, not the AI "Import from PDF" feature) run 5–10 MB on average — above even the fixed 4 MB ceiling.
