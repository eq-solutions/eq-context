# Session 2026-09-02 — pdfrx_engine null-safety bug: local `flutter test` compile failure root-caused, fixed, merged

## Built
- Root-caused why `flutter test` failed to compile on this Windows dev machine (reproduced on 2 unrelated test files): `pdfrx_engine` 0.4.5's `pdf_file_cache.dart` has a genuine null-safety bug — an inner `async` closure (`read: (buffer, position, size) async {...}`) uses bare `cache.blockSize`/`cache.read(...)` on a variable that's only promoted non-null in the *outer* scope. Dart never carries promotion into a captured closure.
- Found why CI stays green despite this: not a platform/scope difference — Dart ≤3.12 had its own soundness bug ([dart-lang/sdk#62889](https://github.com/dart-lang/sdk/issues/62889)) that let the bad promotion leak into the closure anyway; Dart 3.13 fixed it, correctly exposing pdfrx_engine's bug. eq-cards' `ci.yml` is still pinned to Flutter 3.44.8/Dart 3.12.2 (last bumped 2026-08-17 for an unrelated constraint); local SDK here is Flutter 3.47.2/Dart 3.13.2.
- Fixed by bumping the transitive `pdfrx_engine` lockfile entry, `0.4.5 → 0.4.7` (fixed upstream in 0.4.6) — no `pubspec.yaml` change. Empirically confirmed (two different techniques: `pub upgrade pdfrx_engine`, and a hand-edit + plain `pub get`) that pub's solver currently drags 6 unrelated transitive packages (matcher/meta/test/test_api/test_core/vector_math) plus an `analysis_options.yaml` auto-migration into *any* pub resolution in this repo, regardless of scoping technique — none required by pdfrx_engine 0.4.7's own constraints (checked directly) — reverted all of it by hand to keep the shipped diff to the single lockfile entry.
- Verified: both originally-failing files compile and pass (`licence_card_test.dart` 8/8, `licences_list_screen_test.dart` 9/9). A fresh worktree also needed `dart run build_runner build` first (freezed/json_serializable codegen, gitignored, absent in a brand-new worktree) — unrelated to the pdfrx_engine bug, just a prerequisite for anything to compile in a clean checkout.
